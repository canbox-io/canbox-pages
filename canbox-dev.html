Canbox 开发文档

本文档面向 Canbox 平台贡献者，描述平台的三层架构设计、各模块职责、数据目录结构以及构建发布流程。

贡献指南

  1. fork 代码
  2. 提交修改
  3. 提交 pr
  4. 等待合并 😁

Canbox 采用多仓库组织形式，核心仓库包括 canbox-core、canbox-manager、canbox-developer，各仓库独立版本管理，通过共享文件系统（store/db）协作。

架构总览

Canbox 采用 core 注入 + 多 APP 进程模型，三层设计各司其职：

层 定位 职责 是否必需
canbox-core 环境层（服务提供层） 通过 electron -r 预加载，提供统一运行时环境与可选公共服务（store/db/dialog 等） 可选
canbox-manager 管理器 APP APP 注册管理、仓库管理、系统设置（普通 APP，无特殊权限） 可选
canbox-developer 开发工具 APP APP 的调试启动、打包发布等开发便利（普通 APP，无特殊权限） 可选

核心原则

  • APP 首先是标准 Electron 应用，canbox-core / canbox-developer 只是服务层和工具层，不是 APP 运行的前提
  • canbox-core 是环境层，不是框架。隐性能力对 APP 透明，显性 API 通过 IPC 按需调用
  • canbox-manager / canbox-developer 都是普通 APP，不拥有特殊权限，通过 electron -r canbox-core/injection.js 启动
  • 各 APP 进程独立，通过共享文件系统（store/db）通信，而非 IPC
  • store/db 黑盒式，APP 调用时不传 appId，由 core 从 --app-id 自动路由到 data/{appId}/

canbox-core（环境层）

canbox-core 是 Canbox 的核心注入模块，通过 Electron -r（require）标志在 APP 主进程启动前预加载，提供统一运行时环境与可选公共服务。

目录结构

canbox-core/
├── injection.js          # 三阶段编排入口（环境 → API → 运行时）
├── lib/                 # 模块化功能库
│   ├── env.js           # 环境初始化（隐性能力）
│   ├── logger.js        # 统一日志
│   ├── store.js         # 键值存储（electron-store）
│   ├── db.js            # 文档数据库（PouchDB）
│   ├── dialog.js        # 原生对话框
│   ├── window.js        # 窗口管理 / 通知
│   ├── lifecycle.js     # 生命周期回调
│   ├── shortcut.js      # 全局快捷键
│   ├── sudo.js          # 提权执行
│   └── misc.js          # 杂项功能
└── package.json

三阶段启动机制

injection.js 执行三个阶段：

阶段 时机 内容
阶段1：环境初始化 require(injection.js) 时立即执行 userData 路径、config.json 读取 customDataRoot、UsersBase 计算、Users 目录创建、--app-id 解析、module-alias 注册
阶段2：API 注册 同上（同步） 注册所有 ipcMain.handle IPC handlers（store/db 按 appId 黑盒路由）；写 core.injectionPath 到 {Users}/canbox.json
阶段3：运行时初始化 app.whenReady() 后 初始化 log4js logger（写入 {Users}/logs/canbox.log）

隐性能力（对 APP 透明）

能力 实现
统一 userData 路径app.setPath('userData', ~/.config/canbox/)
config.json + customDataRoot读取 customDataRoot 计算 UsersBase
Users 目录结构自动创建 apps/data/db/repos/temp/logs 子目录
appId 解析从 --app-id= 或 package.json name 读取
统一日志log4js 写入 {Users}/logs/canbox.log

显性 API（29 个 IPC 通道）

所有 API 通过 window.api.xxx 调用（由各 APP 的 preload.js contextBridge 暴露）。store/db 为黑盒式，APP 不传 appId，由 core 自动路由到 data/{appId}/。

模块 通道数 主要功能
store4键值存储（get/set/delete/clear）
db7文档数据库（put/get/allDocs/bulkDocs/remove/find/createIndex）
dialog3原生对话框（showMessageBox/showOpenDialog/showSaveDialog）
window2窗口管理（createWindow/notification）
lifecycle1生命周期（registerCloseCallback）
shortcut3全局快捷键（register/unregister/isRegistered）
sudo1提权执行（exec）
misc8杂项（hello/openUrl/getUserData/getCoreVersion/getCorePath/getPlatformInfo/showItemInFolder/openPath）

API 详细签名请参阅 API 文档。

全局变量

injection.js 预加载时将 env 和 corePath 挂到全局变量，供 APP 主进程直接读取（APP 不 npm install canbox-core）：

global.__CANBOX_ENV__ = env;              // { userData, usersBase, usersPath, appId }
global.__CANBOX_CORE_PATH__ = path.resolve(__dirname);  // canbox-core 根目录

canbox-manager（管理器 APP）

canbox-manager 是 Canbox 的管理器 APP，负责 APP 管理（导入/删除/启动/清理数据）、仓库管理（添加/删除/同步）、系统设置（语言/自启/字体/日志保留）。

关键约束：canbox-manager 是普通 APP，通过 electron -r canbox-core/injection.js canbox-manager/ --app-id=canbox-manager 启动，不拥有特殊权限。

目录结构

canbox-manager/
├── main.js                 # Electron 主进程 + manager 专用 IPC handlers
├── preload.js              # contextBridge（canbox-core API + manager API）
├── vite.config.mjs         # Vite 构建配置
├── index.html              # HTML 入口
├── package.json
└── src/                   # Vue 前端源码
    ├── main.js             # Vue 3 入口
    ├── App.vue             # 左侧图标导航 + 右侧内容区
    ├── router/index.js     # 4 路由（Apps / Repos / Settings / About）
    ├── stores/             # Pinia stores
    ├── views/              # 页面组件
    ├── i18n/               # 国际化
    ├── utils/              # 工具函数
    └── assets/             # 静态资源

Manager 专用 IPC Handlers

canbox-manager 的 main.js 在 canbox-core API 基础上，额外注册了 manager 专用 IPC handlers。manager 作为普通 APP，自己的设置/仓库元数据通过 core store 存到 data/canbox-manager/store/（黑盒路由，appId=canbox-manager）。

类别 通道数 主要功能
APP 管理5list / import / remove / launch / clearData
仓库管理4list / add / remove / sync
设置3get / set / getAll
文件任务3create / cancel / list
缩放3 + 1 事件get / set / reset / onZoomChanged

canbox-developer（开发工具 APP）

canbox-developer 是 Canbox 的开发工具 APP，提供 APP 的调试启动、打包发布等开发便利。与 canbox-manager 一样，它也是普通 APP，不拥有特殊权限。

目录结构

canbox-developer/
├── main.js                # Electron 主进程 + developer 专用 IPC handlers
├── preload.js             # contextBridge（canbox-core API + developer API）
├── vite.config.mjs        # Vite 构建配置
├── index.html             # HTML 入口
├── package.json
├── docs/
│   └── APP_DEV.md         # APP 开发指南
└── src/                   # Vue 前端源码
    ├── main.js            # Vue 3 入口
    ├── App.vue            # 主布局
    ├── router/index.js    # 路由配置
    ├── stores/            # Pinia stores
    ├── views/             # 页面组件（ProjectsView 等）
    ├── i18n/              # 国际化
    ├── utils/             # 工具函数
    └── assets/            # 静态资源

主要功能

  • 调试启动：选择项目目录，用 name 作 appId 启动（--app-id={pkg.name}），显式设置 NODE_ENV=development
  • 打包发布：将 APP 打包为 zip 格式（含 app.asar），支持发布到 GitHub Releases
  • 项目元数据读取：从 package.json 读取 APP 元数据（id/name/version/description 等）

数据目录结构

~/.config/canbox/                      # app.getPath('userData')，固定不变
├── config.json                        # 系统配置（customDataRoot 等），永远在此
└── （customDataRoot 未设时，业务数据根 = 此目录）

{UsersBase}/Users/                     # 业务数据根（可由 customDataRoot 整体搬迁）
├── apps/{appId}/                      # 已安装 APP（manager 导入/repo下载时命名）
├── data/{appId}/
│   ├── store/{name}.json             # APP 键值存储（按 appId 物理隔离）
│   └── db/                           # APP 文档数据库（按 appId 物理隔离）
├── db/
│   ├── history/                      # 平台级操作历史
│   └── fileTask/                     # 平台级文件任务
├── repos/                             # 仓库克隆
├── temp/
│   ├── apps/                         # APP 临时文件
│   └── repos/                        # 仓库临时文件
├── logs/
│   └── canbox.log                    # 统一日志
└── canbox.json                        # 平台级配置（core.injectionPath、core.version）

数据隔离模型（黑盒）

层面 机制 APP 是否感知
storedata/{appId}/store/{name}.json否，调 store.set('name','key',val) 自动路由
dbdata/{appId}/db/否，调 db.put(doc) 自动路由
平台级 dbdb/{history,fileTask}/否，仅 manager 主进程直接引用

删 APP 清数据 = rm -rf data/{appId}/，干净利落。

APP 启动流程

启动命令

electron -r canbox-core/injection.js /path/to/app/ --app-id={appId} --no-sandbox

执行顺序

  1. Node.js 加载 canbox-core/injection.js（阶段1 + 阶段2）
  2. 阶段1：env.js 设置 userData、读 config.json、计算 UsersBase、创建 Users 目录、解析 --app-id
  3. 阶段2：注册所有 IPC handlers（store/db 按 appId 黑盒路由）、写 core.injectionPath
  4. app.whenReady() 触发阶段3（logger.init）
  5. Electron 加载 APP 的 package.json 中 main 字段指定的入口
  6. APP 主进程执行，可通过 require('canbox-core') 访问 core 导出

manager 启动 APP 的实现

canbox-manager 通过 manager.apps.launch IPC 启动 APP：

const child = spawn(process.execPath, [
    '-r', coreInjection,
    appPath,
    `--app-id=${appId}`
], {
    detached: true,
    stdio: 'ignore',
    env: { ...process.env, NODE_ENV: 'production' }  // 显式设 production
});
child.unref();

关键：必须显式设置 env.NODE_ENV=production。否则 manager 在开发模式运行时（NODE_ENV=development）会通过默认继承传给子 APP，导致 APP 误判为开发模式（加载 dev server 白屏、无条件开 devTools 等）。

构建与发布

canbox-manager / canbox-developer 开发

# 安装依赖
npm install

# 开发模式（Vite dev server）
npm run dev

# Vite 构建
npm run build

# Electron 启动（需先 build）
npm run start

产品打包

canbox-manager 的产品包采用结构化部署方式，包含共享 Electron 运行时、canbox-core 和 manager APP：

  • canbox-core 作为 extraResources 目录分发，不放在 app.asar 内，确保 pouchdb 等原生模块正常工作
  • bin/ 目录包含启动脚本（Linux: canbox，Windows: canbox.bat），封装 Electron 启动命令
  • 安装时生成 desktop/lnk 快捷方式，StartupWMClass 设为 canbox-manager 以确保任务栏图标关联

自动更新

canbox-manager 内置自动更新功能，采用 GitHub Releases 作为更新源：

  • 启动后 10 秒后台检查更新（非阻塞）
  • 关于页面提供手动「检查更新」按钮
  • 下载安装程序到 os.tmpdir()，使用 GitHub Assets 原始文件名
  • 使用 child_process.spawn 启动安装程序（detached: true, stdio: 'ignore'），然后立即 app.quit()

仓库管理

canbox 没有中心服务器，所有能使用的 app 都靠交流传播 😆

repos 文件就是 app 信息的集合，这是一个 json 格式的描述文件：

{
    "title": "",
    "version": "",
    "repos": [
        {
            "app": "",
            "description": "",
            "history": "",
            "release": ""
        }
    ]
}
