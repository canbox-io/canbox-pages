API 文档

store

使用 electron-store 进行数据存储

存储位置：{userData}/Users/data/{appId}/store/{name}.json

canbox.store.get(name, key)

获取存储的值。

  • 参数
    1. string name - 存储名称，对应不同的 .json 文件
    2. string key - 存储的键
  • 应答 any - 返回存储的值

canbox.store.set(name, key, value)

设置存储的值。

  • 参数
    1. string name - 存储名称，对应不同的 .json 文件
    2. string key - 存储的键
    3. any value - 存储的值
  • 应答 void

canbox.store.delete(name, key)

删除存储的值。

  • 参数
    1. string name - 存储名称，对应不同的 .json 文件
    2. string key - 存储的键
  • 应答 void

canbox.store.clear(name)

清空指定存储的所有数据。

  • 参数
    1. string name - 存储名称，对应不同的 .json 文件
  • 应答 void

注意：每个 name 对应一个独立的 .json 文件，用于存储不同类型的数据。例如：

  • config.json - 应用配置
  • user.json - 用户数据
  • cache.json - 缓存数据

Canbox 为每个 APP 生成单独的 pouchdb 存储

canbox.db.put(doc)

新增/修改数据文档

注意：创建文档时，如果没有 _id，canbox 会生成一个 _id 最后在应答内容中返回给 app

想要修改文档，参数 _rev 使必须的

  • 参数 object
  • 应答 object

canbox.db.bulkDocs(docs)

批量操作文档，支持新增、修改和删除。

  • 参数 array docs - 文档数组
  • 应答 array - 每个文档的操作结果

功能说明：

  • 新增文档：当文档没有 _id 或没有 _rev 时，canbox 会自动生成 _id 并插入新文档
  • 修改文档：当文档包含 _id 和 _rev 时，会更新现有文档
  • 删除文档：当文档包含 _deleted: true 参数时，会删除该文档（需要提供 _id 和 _rev）

注意：canbox 会自动为新文档生成 createTime，为更新文档生成 updateTime。

canbox.db.get(query)

  • 参数 object
  • 应答 object

canbox.db.allDocs(options)

获取数据库中的所有文档。

  • 参数 object options - 查询选项
  • 应答 object - 包含 total_rows、offset、rows 的结果对象

参数说明：

  • include_docs - 是否返回完整文档内容（默认 false）
  • limit - 限制返回的文档数量
  • descending - 是否倒序排列
  • startkey - 开始的文档 ID
  • endkey - 结束的文档 ID
  • skip - 跳过的文档数量

注意：allDocs 会返回数据库中的所有文档，适合用于数据遍历、统计等场景。如果只需要特定条件的文档，建议使用 find() 方法。

canbox.db.remove(doc)

  • 参数 object 需要包含 _id 和 _rev
  • 应答 object

canbox.db.find(query)

使用 Mango 查询语法查询文档。

  • 参数 object query - 查询条件对象，支持 Mango 查询语法
  • 应答 object - 包含 docs 数组的查询结果

注意：find 方法使用 PouchDB 的 Mango 查询语法，支持复杂的查询条件、排序、分页等功能。

canbox.db.createIndex(index)

创建索引以提升查询性能。

  • 参数 object index - 索引配置对象
  • 应答 object - 索引创建结果

性能提示：

  • 创建索引可以显著提升 find 查询性能
  • 建议在应用初始化时创建常用的索引
  • 索引创建是异步操作，建议在应用启动时完成

window

提供窗口创建和系统通知能力。

canbox.window.createWindow(options)

创建一个新的 BrowserWindow 并返回窗口 ID。

  • 参数
    1. object options - 参考 electron：BrowserWindowConstructorOptions。不传则使用默认值（800x600，contextIsolation: true，nodeIntegration: false）
  • 应答 object - 包含 success 和 windowId 的对象

注意：canbox-core 只负责创建窗口对象，APP 需自行管理窗口的加载内容（loadURL/loadFile）、生命周期事件等。通常 APP 在自己的 main.js 中直接 new BrowserWindow()，仅在需要额外窗口时调用此 API。

canbox.window.notification(options)

显示系统通知。

  • 参数 object options - 参考 electron：Notification 构造选项（title、body、icon 等）
  • 应答 object - 包含 success 的对象

全局快捷键

封装 Electron globalShortcut API，提供全局快捷键的注册、注销和查询功能。

canbox.shortcut.register(accelerator, options)

注册全局快捷键。

  • 参数
    1. string accelerator - 快捷键组合，如 'CommandOrControl+Shift+D'
    2. object options - 注册选项
      • mode: mode: 触发模式，'focus'（默认，聚焦窗口）或 'callback'（发送事件到渲染进程，可通过 'canbox:shortcutTriggered' 监听）
  • 应答 object - 成功返回 { success: true }，失败返回 { success: false, reason: 'system-occupied' }

canbox.shortcut.unregister(accelerator)

注销已注册的全局快捷键。

  • 参数 string accelerator - 快捷键组合
  • 应答 object - 成功返回 { success: true }，未注册返回 { success: false, reason: 'not-registered' }

canbox.shortcut.isRegistered(accelerator)

检查快捷键是否已注册。

  • 参数 string accelerator - 快捷键组合
  • 应答 boolean - 是否已注册

sudo

封装 @vscode/sudo-prompt，提供需要管理员/root 权限的命令执行。

canbox.sudo.exec(command, options)

执行需要提权的命令。

  • 参数
    1. string command - 要执行的命令
    2. object options - 提权选项，参考 @vscode/sudo-prompt
  • 应答 object - 包含 stdout 和 stderr 的执行结果

options 参数说明：

  • name - 操作名称，用于向用户提示为何需要提权

name 参数要求：

  • 只能包含字母、数字和空格（不支持中文等非 ASCII 字符）
  • 长度不超过 70 个字符
  • 建议使用英文描述，例如：'Apply Hosts Config'、'Restart Service'

注意：提权操作涉及系统安全，请谨慎使用。确保只执行必要的命令，并在 name 参数中清晰说明操作目的。

dialog

封装 Electron dialog API，提供原生对话框。所有对话框自动绑定到当前焦点窗口。

canbox.dialog.showMessageBox(options)

  • 应答 object - 包含 canceled、filePaths

canbox.dialog.showSaveDialog(options)

显示文件保存对话框。

  • 参数 object options - 与 Electron dialog.showSaveDialog 一致
  • 应答 object - 包含 canceled、filePath

生命周期

提供 APP 生命周期相关的回调注册。

canbox.lifecycle.registerCloseCallback()

注册当前窗口关闭前的回调。注册后，当窗口关闭时会向渲染进程发送 'canbox:lifecycleCloseCallback' 事件，APP 可在 preload.js 中通过 ipcRenderer.on 监听。

  • 参数：无（自动绑定调用方所在窗口）
  • 应答 object - 成功返回 { success: true }，无窗口时返回 { success: false, error: '...' }

使用示例：

// preload.js
const { contextBridge, ipcRenderer } = require('electron');
contextBridge.exposeInMainWorld('api', {
    lifecycle: {
        registerCloseCallback: () => ipcRenderer.invoke('canbox.lifecycle.registerCloseCallback'),
        onCloseCallback: (callback) => ipcRenderer.on('canbox:lifecycleCloseCallback', callback)
    }
});

// 渲染进程
window.api.lifecycle.registerCloseCallback();
window.api.lifecycle.onCloseCallback(() => {
    // 执行清理逻辑，如保存数据
});
