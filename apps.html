APP 中心

发现和安装基于 Canbox 开发的应用

  1. 开发你的应用

    基于 Canbox 开发你的 Electron 应用，确保项目包含 package.json（含 name、version、main、author、description 字段）。

  2. 添加 .canbox-app 文件

    在仓库根目录创建 .canbox-app 文件（JSON 格式），声明应用类型和元数据：

    {
  "type": "native",
  "electron": {
    "range": "42.5.1"
  },
  "category": "development",
  "tags": ["json", "formatter"],
  "description": "JSON 格式化工具",
  "description_en": "JSON formatter",
  "logo": "logo.png"
}

    通过 GitHub 仓库发布的开发者应用，type 只能是 native，并必须填写 electron.range。web 类型仅用于 canbox-manager 内部创建的网页应用；PWA 是网页应用的一种形态，不属于仓库发布流程，也不应作为 type 值使用。

  3. 打包并发布 GitHub Release

    按 canbox 标准结构打包 zip，然后创建 GitHub Release。tag 使用 v{version} 或 {version}，并把 zip 作为 Release 资产上传。

    {id}-{version}.zip
├── app.asar
├── app.asar.unpacked/   (optional)
├── package.json
└── logo.png

    资产名必须为 {id}-{version}.zip；没有 id 时使用 {name}-{version}.zip。只把 zip 提交到源码仓库、没有对应 Release 资产时，用户点击下载会失败。

    查看完整发布流程

  4. 添加 canbox-app Topic

    在 GitHub 仓库的 Settings → Topics 中添加 canbox-app 标签。系统会自动发现你的应用，无需提交 PR。

注意事项

  • Catalog 收录不等于可下载：收录只检查 topic、.canbox-app 和 package.json，下载还需要对应的 GitHub Release 资产
  • 新仓库添加 topic 后通常在下一个整点被发现；已创建仓库后补 topic 需等待每周一的全量对账（reconcile），需要立即收录时可手动触发 Reconcile workflow
  • .canbox-app 文件中的 type 字段必填且固定为 native；不应使用 web 或 pwa，web 类型仅限 canbox-manager 内部创建的网页应用
  • native 类型应用必须填写 electron.range 字段
  • logo 文件路径相对于仓库根目录，默认取 logo.png
  • category 可选值：development / utility / office / network / audio / video / game / graphics / education，缺失或非法值归为 other
